## 1. 项目结构

| 包 | 职责 | 关键类 |
|---|------|--------|
| config | Spring 配置类 | RedisConfig, MyBatisPlusConfig |
| controller | 路由 + 参数校验 + 调用 Service | MenuController |
| service.impl | 业务编排（缓存检查 -> Chain 调用） | MenuServiceImpl |
| service.chain | 责任链核心（编排 5 个 Handler） | MenuHandlerChain, MenuContext, MenuHandler |
| service.chain.handler | 5 个 Handler 实现 | LegacyCheckHandler(@Order(1)), LoadMenuHandler(@Order(2)), FallbackMatchHandler(@Order(3)), PermissionFilterHandler(@Order(4)), TreeBuildHandler(@Order(5)) |
| service.cache | Redis 缓存服务 | MenuTreeCacheService |
| mapper | MyBatis 数据访问接口 | MenuConfigMapper, BranchConfigMapper |
| model.entity | DB 表一一映射 | MenuConfig, BranchConfig |
| model.dto | 入参（含 @Valid 校验） | MenuQueryDTO |
| model.vo | 出参（必须实现 Serializable） | MenuTreeVO, MenuNodeVO |
| enums | 魔法值统一定义 | ChannelEnum |
| exception | 业务异常 | BusinessException(code, message) |
| constant | 常量 | CacheConstant |

**请求链路**：Controller -> Service(缓存检查) -> HandlerChain(5 个 Handler) -> Mapper -> MySQL / Redis

## 2. 编码红线（必须遵守，违反就报错）

| 编号 | 规则 |
|------|------|
| R-1 | Controller 不写业务逻辑，不直接调用 Mapper |
| R-2 | Service 只做编排，具体业务逻辑下沉到 Handler 或独立 Service |
| R-3 | 禁止魔法值，必须用枚举或常量 |
| R-4 | VO 类必须实现 Serializable |
| R-5 | 方法体不超过 80 行，超过必须拆分 |
| R-6 | 禁止 System.out.println，统一用 @Slf4j |
| R-7 | 异常必须走 BusinessException 或 GlobalExceptionHandler |
| R-8 | Entity 字段下划线自动映射驼峰，禁止手动 @TableField |
| R-9 | Handler 必须加 @Component + @Order，忘了加 @Order 会排到最后 |
| R-10 | Handler 只处理 MenuContext，不写 Controller 逻辑，不直接操作 DB |
| R-11 | MenuTreeVO / MenuNodeVO 已存在，不要重复创建同名类 |

## 3. 开发顺序（自下而上）

按以下顺序逐层编码，上层依赖下层：

1. **数据层**：DB 表 -> Entity -> Mapper 接口 + XML
2. **业务层**：DTO -> Service 接口 -> Service 实现（编排版）
3. **架构层**（按需）：需要新 Handler 就新建类 + @Order；需要新缓存就在 cache 包扩展
4. **接入层**：Controller -> Result<T> 统一返回 -> GlobalExceptionHandler
