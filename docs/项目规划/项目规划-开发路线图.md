## 阶段一：核心链路跑通 + 架构重构 ✅

### 目标
一个最小可用后端：能接请求、能查库、能跑 5 步流水线、能返回正确 JSON。
加架构重构：用责任链模式解耦业务步骤，加 Redis 缓存。

### 做了什么
| 模块 | 具体事项 |
|------|---------|
| **环境搭建** | Docker 起 MySQL 8.0 + Redis 7；Spring Boot 3.4.4 + MyBatis-Plus |
| **数据层** | `menu_config` + `branch_config` 建表；Entity + Mapper 定义 |
| **业务层核心** | `MenuFallbackService`（四维通配 + 精确优先去重）、`PermissionFilter`、`MenuTreeBuilder`（单趟 idMap 组树，O(n)）、Legacy 分流开关 |
| **接入层** | `MenuController`（POST `/api/menu/tree`）、`Result<T>` 统一返回、`GlobalExceptionHandler`、`@Valid` 参数校验 |
| **种子数据** | 25 条菜单配置 + 7 条分行配置，覆盖 Fallback、权限、Legacy 三大场景 |
| **🏆 责任链重构** | 5 个 Handler 按 `@Order` 串联：LegacyCheck → LoadMenu → FallbackMatch → PermissionFilter → TreeBuild；加步骤只需要新建 Handler 类实现 `MenuHandler` 接口，符合开闭原则 |
| **🏆 Redis 缓存** | `MenuTreeCacheService` 封装 Redis 读写；缓存 key = `menu:tree:{branchCode}:{userId}`，TTL 10 分钟；`MenuServiceImpl` 先查缓存 → miss 走责任链 → 回写缓存 |

### 设计亮点（面试素材）

#### 责任链模式
```
怎么跑的？
  MenuServiceImpl.buildMenuTree()
    → cacheService.get()              // Redis 命中直接返回
    → new MenuContext() + handlerChain.proceed(context)
      → LegacyCheckHandler(@Order(1))  // 分支用 Legacy？提前返回空树，链终止
      → LoadMenuHandler(@Order(2))     // 拉全活菜单，存 context
      → FallbackMatchHandler(@Order(3)) // Fallback 匹配，存 context
      → PermissionFilterHandler(@Order(4)) // 权限过滤，存 context
      → TreeBuildHandler(@Order(5))    // 组树，设置 context.result

怎么加新步骤？
  新建类 implements MenuHandler + @Order(6) { ... }
  实现 handle() 方法，操作 context，然后链自动继续（除非设置 result 终止）
  ✅ 开闭原则：加步骤不改老代码
```

#### Redis 缓存
```
缓存 key:    menu:tree:{branchCode}:{userId}  （userId=null 用 anonymous）
缓存 value:  MenuTreeVO（整个菜单树 JSON）
TTL:         10 分钟
序列化:      GenericJackson2JsonRedisSerializer（RedisConfig 配置）

缓存流程:
  请求 → cacheService.get()
    → 命中？直接返回 ✅
    → 未命中？handlerChain.proceed() → cacheService.put() → 返回

为什么用 branchCode + userId？
  不同分行菜单不同（Fallback 匹配），不同用户权限不同（权限过滤）
  组合起来才是最终看到的菜单树
```

### 踩过的坑（简历素材）
| 坑 | 解法 | 面试怎么讲 |
|----|------|----------|
| Spring Boot 4 + MyBatis-Plus 不兼容 | 降级到 3.4.4 | 选型注意社区生态匹配 |
| 全局 `@TableLogic` 导致无 `is_deleted` 字段的表 SQL 报错 | 改 Entity 级注解 | 全局配置要谨慎 |
| JDBC URL 写 `utf8mb4` 报 `UnsupportedEncodingException` | 改成 Java 标准字符集 `UTF-8` | MySQL 字符集 ≠ Java 字符集 |
| PowerShell 写 Java 文件带 BOM | `[System.IO.File]::WriteAllText` 无 BOM | 跨环境编码问题 |
| 根节点判定写 `parentId == null` 导致返回空树 | 数据库存的是 `0` 不是 null，改成 `parentId == null \|\| parentId == 0L` | 写代码先看实际数据，别脑补约定 |
| Redis 序列化用默认 JDK，存进去一堆 `\xac\xed` | 配置 `GenericJackson2JsonRedisSerializer` | 线上缓存必须存可读 JSON，方便排查 |

## 阶段二：工程化 & 稳定性 🔧

### 目标
系统能扛住流量、改代码不怕炸、出问题能排查。

### 2.1 Redis 缓存 ✅ 已完成
见阶段一"责任链重构 + Redis 缓存"部分。

### 2.2 单元测试 🔲
**为什么**：`MenuFallbackService.match()` 是整个系统最复杂的算法——四维通配 + 精确优先去重。改一行代码可能 silently 把 Fallback 优先级搞反。必须有测试兜底。

**测什么**：
| 测试类 | 核心用例 |
|--------|---------|
| `MenuFallbackServiceTest` | ① 全局配置匹配所有人 ② 精确配置只匹配特定分行 ③ node_id 去重时精确优先 ④ 空输入返回空列表 ⑤ 混合精确度场景 |
| `MenuTreeBuilderTest` | ① parent_id=0 的做根节点 ② 父子递归关联 ③ 孤儿节点（parent_id 不存在）不挂树 ④ 空列表返回空 |
| `PermissionFilterTest` | ① 无 requiredPerm 的节点所有人可见 ② 有权限的人看，无权限的人砍 ③ null permissions 视为无权限 |
| `MenuHandlerChainTest` | ① Handler 按 @Order 顺序执行 ② 设置 result 后链终止 ③ 正常走完整条链 |

### 2.3 日志完善 + 链路 Tracing 🔲
**为什么**：线上出了问题（"为什么这个用户看不到数字人民币？"），得能从一条请求看到全链路日志。

**怎么做**：
- MDC（Mapped Diagnostic Context）注入 `traceId`，一条请求的所有日志都带同一个 ID
- 关键节点打 `info` 日志：Fallback 匹配了几条、权限过滤砍了几条、组树几个根
- 异常 `error` 日志带完整堆栈
- 接入 SkyWalking 或 Spring Cloud Sleuth（后续如果走微服务）

### 2.4 接口文档（OpenAPI/Swagger）🔲
**为什么**：前端要调接口，得知道请求参数是什么、返回格式是什么。手写文档容易过时。

**怎么做**：加 `springdoc-openapi-starter-webmvc-ui` 依赖，访问 `http://localhost:8080/swagger-ui.html` 自动生成。

### 2.5 参数校验完善 🔲
**为什么**：现在 `@NotBlank` 只能校验"非空"，还需要校验格式（countryCode 是不是两位大写字母？）。

**怎么做**：加自定义校验注解 `@CountryCode`、`@EntityCode`，或者用正则 `@Pattern`。

### 完成标志
- [x] 菜单树有 Redis 缓存，连续两次 curl 第二次不查库
- [ ] `MenuFallbackServiceTest` 10+ 用例全绿
- [ ] 一条请求的日志可通过 traceId 串联
- [ ] Swagger UI 可访问，接口定义自动生成

## 阶段三：生产就绪 🏭

### 目标
能部署到服务器、能抗住线上流量、出问题能快速恢复。

### 3.1 多环境配置
**为什么**：开发环境连本地 Docker、测试环境连测试库、生产环境连生产库。不能每次改 yaml 切换。

**怎么做**：
```
src/main/resources/
├── application.yaml              ← 公共配置
├── application-dev.yaml          ← 开发环境（localhost MySQL）
├── application-staging.yaml      ← 测试环境
└── application-prod.yaml         ← 生产环境
```
启动时 `java -jar app.jar --spring.profiles.active=prod`

### 3.2 CI/CD 自动化
**为什么**：不能每次手动打包上传。

**怎么做**：
- GitHub Actions / GitLab CI：push 代码自动跑测试 → 打包 → 构建 Docker 镜像 → 推到镜像仓库
- 部署用 docker-compose 或 K8s

### 3.3 监控告警
**为什么**：线上挂了得有人知道。

**怎么做**：
- Spring Boot Actuator 暴露健康检查、指标
- Prometheus + Grafana 监控：接口 QPS、响应时间、Redis 命中率、MySQL 连接池
- 告警规则：5 分钟内 5xx 超过 1% 触发报警

### 3.4 权限服务对接
**为什么**：现在 `mockUserPermissions()` 返回的是硬编码，真实场景要从下游 IAM 系统查用户权限。

**怎么做**：
- 从请求 Header 拿 Token → 调 IAM 接口 → 拿到权限列表 → 传给 `PermissionFilter`
- 注意权限结果也要缓存（Redis TTL 30 分钟）

### 3.5 Legacy 客户端对接
**为什么**：HK、BM 等老分行还在用旧系统，`use_legacy_menu=1` 时不能返回空，要转发到旧系统。

**怎么做**：
- `RestTemplate` 或 `WebClient` 调旧系统接口
- 结果透传给前端（或做格式转换）
- 设置超时（connect 2s + read 5s），旧系统挂了快速失败

### 3.6 灰度发布
**为什么**：新菜单逻辑不能一下子全量上线，得逐分行灰度。

**怎么做**：
- 用现有 `branch_config.use_legacy_menu` 反向利用：`use_legacy_menu=0` 表示已切新平台
- 每次上线改一个分行的开关，观察 1-2 天没问题再改下一个

### 完成标志
- [ ] 三个环境（dev/staging/prod）可切换
- [ ] push 代码 → 自动部署到 staging
- [ ] Prometheus 面板能看到接口指标
- [ ] 真实权限服务对接完成，mock 代码删掉
- [ ] 至少一个 Legacy 分行的转发跑通
- [ ] 灰度迁移流程跑通 1 个分行

## 阶段四：业务扩展 & 持续迭代 🚀

### 目标
从"能用"到"好用"，支撑更多业务场景。

### 4.1 面包屑导航
**为什么**：前端不只要树，还要知道"我从哪来"——用户点进"行内转账"，顶部要显示 `首页 > 转账汇款 > 行内转账`。

**怎么做**：`MenuTreeVO` 里加 `breadcrumb` 字段，组树时同时回溯路径（可以在 `MenuTreeBuilder` 里顺便做）。

### 4.2 菜单版本管理
**为什么**：改菜单配置前想先预览？误改了想回滚？需要版本控制。

**怎么做**：新建 `menu_config_history` 表，每次改配置前快照一份，支持"回滚到 v3"。

### 4.3 菜单发布审批流
**为什么**：生产库不能随便改。运营改菜单 → 提交审批 → 技术 Review → 发布。

**怎么做**：新建 `menu_publish_request` 表，状态机 `draft → pending_review → approved → published / rejected`。

### 4.4 多语言国际化
**为什么**：国际银行场景，同一菜单要显示中文、英文、繁体。

**怎么做**：`menu_config` 表加 `node_name_en`、`node_name_tw` 字段，根据请求的 `locale` 参数返回对应语言。

### 4.5 前端对接 & 菜单管理后台
**为什么**：运营不能直接改数据库，需要一个界面来管理菜单配置。

**怎么做**：
- 前端 Vue/React 做菜单管理页面（CRUD + 拖拽排序）
- 后端加 `MenuConfigAdminController`（增删改 + 批量导入 + 版本回滚）
- 改完菜单自动删 Redis 缓存（`cacheService.evict(branchCode, userId)`）

### 完成标志
- [ ] 面包屑返回正确路径
- [ ] 菜单可回滚
- [ ] 至少一个分行走通"运营改菜单 → 审批 → 发布"全流程
- [ ] 英文菜单可切换
- [ ] 运营能用管理后台改菜单，不用碰数据库
